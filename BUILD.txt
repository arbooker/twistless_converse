Building and verifying the supplementary material

The written proofs are in pdf/. The formal proofs use Lean 4.35.0-rc2
(commit 11acb17ec6b07a8f9e9173e6845197929540936b) and Mathlib commit
065356127b1dc0016f66b7283ce0ce2c4055aa55. Transitive dependencies are pinned
in lean/lake-manifest.json. Install elan and Python 3, then run:

  cd lean
  python3 verify_release.py --recorded-reports
  lake exe cache get
  lake env python3 check_proofs.py

The first command verifies source hashes, package files and the supplied
endpoint axiom logs. It does not compile Lean. The last command checks every
module with Lean's kernel and verifies the 17 endpoint axiom reports. Only
propext, Classical.choice and Quot.sound are permitted in those reports.
No native_decide, custom mathematical axioms or sorry are used in the proofs.

check_proofs.py runs one compiler at a time, with one compiler thread and a
6 GiB Lean memory limit. Use --memory-mib to adjust that limit. There is no
per-file time limit. Successful modules are cached under .lake/proof-check;
rerunning resumes from matching source and dependency fingerprints. All six
theorem roots are checked separately. SOURCE_MANIFEST.json lists their
statements and complete dependency closure.

For a standard Lake build, run lake build FinitenessProof. Lake manages its
own scheduling; allow sufficient aggregate memory for concurrent compilers.
The lakefile and sequential checker disable asynchronous elaboration and
linters that depend on editor information omitted by compact certificates.
They remove the elaboration heartbeat limit, while retaining kernel checks
and treating other warnings as errors. Do not update the pinned dependencies
when reproducing this release. Keep build products outside cloud-synchronized
folders.

The formal proof covers fixed-growth finiteness, the radical-range M_k^circ
count, all 34 small levels, the prime small-conductor converse and primitive
twist corollary, the spanning criterion, and the short-interval Weyl asymptotic
for the original Maass Euler-product solution count at all admissible levels.

Numerical programs

Follow numerics/README.md for compiler, FLINT and OpenMP requirements.
Preserve the pinned third_party/cado-nfs submodule for the sparse pipeline.
The companion calculations and recorded inputs are in small_levels/;
its README.txt explains prerequisites and generator ordering.

Verification records

lean/verification/checked-endpoints.json records the checked source and
recursive dependency hashes, compiler pins and named axiom reports. The
corresponding compiler output is in lean/verification/logs/.
The records under provenance/ document the numerical programs and PDF
writeups. SOURCE_MANIFEST.json records hashes of all release artifacts.
